# Release procedure

Use a Windows x64 checkout with the .NET 10 SDK. Keep personal profiles, logs, credentials,
compiler caches, and device identifiers out of Git and release assets.

1. Set `Directory.Build.props` to the release version and update the manifest, installer fallback
   version, changelog, documentation, and demo screenshots. UI version text comes from the assembly.
2. Run `tools/Build.ps1 -Test`. Core regressions and WPF demo UI checks must pass.
3. Run `tools/Package.ps1 -SkipTests` and `tools/Build-Installer.ps1`. The package is self-contained,
   includes runtime licenses, and has a SHA-256 manifest. Installer compilation rejects version or
   payload mismatches. `Restore-InstallerTools.ps1` retrieves a pinned, publisher-verified compiler.
4. On an existing installation, run `tools/Test-Upgrade.ps1`. It checks real upgrade version/path,
   settings retention, payload hashes, startup enabled/disabled transitions, and explicit task overrides.
   It restores the original startup entry. It leaves the new version installed.
5. On a clean Windows user profile, run `tools/Test-Installer.ps1` for install/update/uninstall checks.
   CI also runs this when its Windows runner exposes an interactive desktop.
6. Run `tools/Test-App.ps1 -Executable <installed-exe> -Hardware -Startup`. Confirm each supported
   brightness and contrast control changes and returns to its exact original value. Preserve JSON
   receipts locally. Inspect the real panel, main window, light/dark/minimum-size layouts, and tray.
7. Review `docs/VALIDATION.md`. Do not turn source, synthetic, or readback results into claims about
   other hardware, physical luminance, Windows versions, reboot/sign-in, HDR, docking, or signing.
8. Review the diff and staged files, commit, push, and require a successful Windows CI run.
9. Tag the reviewed commit. Publish `OmniLux-Setup.exe`, `OmniLux-<version>-win-x64.zip`, and
   `SHA256SUMS.txt` to that GitHub release. Verify uploaded SHA-256 digests against local files and
   verify the public repository branch/tag match the reviewed commit. Keep older releases available.

The portable ZIP contains a versioned root folder. Extract the entire folder; moving just the EXE
loses its self-contained runtime and resources. The installer uses a stable application ID so
upgrades retain their location and user data. Startup is optional and per user.

## Signing preparation and current boundary

Current public binaries are unsigned. A valid publisher signature requires a trusted code-signing
certificate and access to its private key; neither is assumed or generated by OmniLux.
Do not label an unsigned package as publisher-signed or bypass Windows security settings.

For a future signed distribution, sign `OmniLux.exe` with the intended publisher using the Windows
SDK SignTool, SHA-256 file digests, and an RFC 3161 SHA-256 timestamp. Verify the signature and
publisher, then regenerate the package manifest and ZIP before compiling the installer. Configure
Inno Setup's supported signing/SignedUninstaller workflow so the uninstaller and setup are signed
by the same publisher. Verify the final installed executable, setup, and uninstaller signatures,
regenerate release checksums, and repeat clean install/upgrade/uninstall acceptance on a separate PC.
Signing also needs publisher and certificate checks in the build scripts before changing the
package's `publisherSigned` field. SmartScreen reputation is a separate release consideration.
